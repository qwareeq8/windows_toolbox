**Windows Toolbox.spec -> Virelo.spec** -- Per D-03, rename the file using `git mv "Windows Toolbox.spec" Virelo.spec`. Then prepend a version extraction block at the top of the file (after the `# -*- mode: python ; coding: utf-8 -*-` line):

```python
import re
from pathlib import Path

# Parse APP_VERSION via regex -- do NOT import app_config directly.
# Importing app_config in spec context may trigger PySide6 import chain.
_cfg = Path("app_config.py").read_text()
_match = re.search(r'APP_VERSION\s*=\s*"([^"]+)"', _cfg)
APP_VERSION = _match.group(1) if _match else "0.0.0"
```

Do NOT use `from app_config import APP_VERSION` -- the spec runs in PyInstaller's analysis context where PySide6 may not be importable (RESEARCH.md Pitfall 4).

**installer/virelo.iss** -- Per D-05 and RESEARCH.md Pattern 2, replace line 5 (`#define MyAppVersion "1.4.2"`) with a `#ifndef` guard:

```pascal
#ifndef MyAppVersion
  #define MyAppVersion "0.0.0-dev"
#endif
```

This allows the build script to pass `/DMyAppVersion=X.Y.Z` via ISCC command line while keeping a fallback for manual compilation. Do NOT use an unconditional `#define` -- it would silently override the `/D` flag (RESEARCH.md Pitfall 3).

**frontend/vite.config.js** -- Per D-01 and RESEARCH.md Pattern 1, add a `define` block after `base: './'`:

```javascript
define: {
  __APP_VERSION__: JSON.stringify(process.env.VITE_APP_VERSION || 'dev'),
},
```

CRITICAL: Must use `JSON.stringify()`. Without it, the value is treated as a JS expression, not a string literal (RESEARCH.md Pitfall 1). The `VITE_APP_VERSION` env var will be set by `build-frontend.ps1` (Plan 03).
